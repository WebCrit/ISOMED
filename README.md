# Isomed — إصلاح 404 والنشر

هذا موقع HTML ثابت: لا يحتاج Node.js أو قاعدة بيانات. ارفع `index.html` مع مجلد `assets/` وملفي `favicon.svg` و`404.html`؛ لا ترفع ملف HTML وحده، لأن صور المنتجات محفوظة محليًا داخل `assets/`.

## لماذا يظهر 404؟

المستودع يحتوي `index.html` في المجلد الرئيسي، لكن رابط GitHub Pages المتوقع `https://alaa421621.github.io/isomed/` أرجع HTTP 404 عند الفحص، وواجهة GitHub API لم تُظهر إعداد Pages للمستودع. هذا يعني أن المشكلة في تفعيل النشر أو عنوان الموقع، وليس في غياب صفحة `index.html` عن المستودع. رابط `github.com/alaa421621/isomed` هو صفحة ملفات الكود، وليس موقع الشركة المنشور.

كما أن دليل cPanel القديم يطلب رفع الملف إلى `public_html` ثم زيارة `/02/`. هذان المساران لا يتطابقان: إذا رفعت الملفات مباشرة إلى جذر الدومين فالعنوان يكون `https://example.com/`. أما `https://example.com/02/` فيتطلب أن تضع الملفات داخل مجلد `02` تحت جذر الدومين. كذلك، الصور المحلية تستلزم رفع مجلد `assets/` مع الصفحة.

## النشر على GitHub Pages

1. افتح المستودع على GitHub ثم **Settings → Pages**.
2. في **Build and deployment** اختر **Deploy from a branch**.
3. اختر الفرع `main` والمجلد `/(root)` ثم اضغط **Save**. يجب أن يكون `index.html` في المستوى الأعلى من المصدر المختار، وهو موجود هنا بالفعل.
4. انتظر اكتمال النشر في تبويب **Actions**، ثم افتح `https://alaa421621.github.io/isomed/`.

استخدم المسار أعلاه لمستودع اسمه `isomed` تحت حساب `alaa421621`، وليس رابط المستودع `github.com/...`. الصور في الموقع تستخدم مسارات نسبية مثل `assets/factory.jfif`؛ لذلك تعمل من المسار الفرعي `/isomed/` في GitHub Pages ومن جذر الدومين أيضًا. تعليمات GitHub الرسمية تسمح بالنشر من مجلد الجذر أو `docs` على الفرع المختار: [مصدر النشر في GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## النشر على cPanel

1. افتح **Domains** في cPanel أو **File Manager → Settings → Document Root for** واختر الدومين الصحيح؛ لا تفترض أن كل دومين يستخدم `public_html`. توثيق cPanel يتيح اختيار جذر الويب أو جذر الدومين المحدد: [cPanel File Manager](https://docs.cpanel.net/cpanel/files/file-manager/).
2. ارفع ملف `isomed-static-site.zip` إلى جذر الدومين الصحيح، ثم استخدم **Extract**.
3. تأكد أن `index.html` موجود مباشرة في ذلك الجذر، وأن مجلد `assets/` بجانبه. لا تضع الملفات داخل مجلد إضافي غير مقصود مثل `public_html/isomed-static-site/`.
4. إذا أردت العنوان `https://example.com/02/` بدلًا من الدومين الرئيسي، أنشئ `02` داخل جذر الدومين وضع محتويات الأرشيف داخله؛ اجعل `index.html` و`assets/` داخله مباشرة.
5. افتح العنوان المطابق لمكان الملفات: الجذر يعني `/`، والمجلد الفرعي `02` يعني `/02/`. تأكد من حالة HTTP 200 للصفحة والصور ومن كتابة أسماء الملفات بحروفها الصحيحة.

توثيق cPanel يذكر أن رفع الملفات يتم إلى جذر الويب أو جذر الدومين المختار عبر File Manager، ويمكن رفع ZIP ثم استخراجه. أرشيف الموقع الجاهز يضم الصفحة والصور اللازمة حتى لا تنسى مجلد الأصول.

## فحص سريع عند استمرار 404

- تحقق أن النشر اكتمل وأن المصدر المختار هو `main` و`/(root)`، أو أن مزود الاستضافة يشير إلى مجلد الدومين الصحيح.
- تأكد أن اسم الصفحة هو `index.html` بحروف صغيرة، وأنها ليست داخل مجلد متداخل دون قصد.
- افتح `https://example.com/assets/factory.jfif` (أضف `/isomed/` على GitHub Pages)؛ يجب أن تُعرض الصورة. إذا عادت 404، ارفع مجلد `assets/` كاملًا إلى جانب `index.html`.
- لا تستخدم `/02/` ما لم تكن الملفات فعلًا داخل مجلد `02`.
- بعد النشر، افحص سجل النشر في GitHub Actions أو راجع جذر الدومين وإعدادات DNS لدى شركة الاستضافة. إعادة تحميل المتصفح لا تصلح مسارًا خاطئًا.

## ملاحظات على الموقع الأصلي

- ملف `CPANEL_INSTALLATION.md` الأصلي يذكر ملف ZIP غير موجود في المستودع ويقول إن `index.html` هو الملف الوحيد، بينما الصفحة تستخدم صورًا محلية عديدة. الأرشيف المرفق هنا يعالج ذلك.
- صورة الـHero كانت تعتمد على رابط CDN موقّع ومؤقت؛ استُبدلت بصورة محلية.
- قائمة الهاتف كانت تختفي دون زر لفتحها. أضيف زر قائمة، وأُصلح رابط الشعار `#` حتى لا يسبب خطأ JavaScript.
- نموذج التواصل يرسل إلى خدمة خارجية `FormSubmit` والبريد `info@isomed.com.eg`. هذا ليس سبب 404 للصفحة، لكن يجب التأكد من إعداد/تأكيد البريد لدى الخدمة، ولا تعرض الصفحة رسالة نجاح قبل استجابة الخدمة.
- نصوص الاعتماد والشهادات الموجودة بالمحتوى الأصلي يلزم التحقق من صلاحيتها وأرقامها قبل استخدامها رسميًا.
